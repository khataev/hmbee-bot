## Context

Функция `mapTochkaCategory` в `src/apply/preview/tochka.ts` (строка 697) определяет категорию транзакции. Текущий порядок: MCC → title-паттерны. MCC — широкий код индустрии (один код покрывает несколько семантически разных merchant'ов). Title-паттерны — явные regex'ы, привязанные к конкретному merchant'у, поэтому они точнее.

Единственный call site — строка 633 той же функции. Изменение затрагивает только эту функцию.

```ts
// Текущая реализация
function mapTochkaCategory(description, mcc, categoryMapping) {
  if (mcc && categoryMapping.mcc[mcc]) return categoryMapping.mcc[mcc]; // MCC первый
  for (const { pattern, entry } of categoryMapping.title) {
    if (pattern.test(description)) return entry;
  }
  return null;
}
```

## Goals / Non-Goals

**Goals:**
- Title-паттерны имеют приоритет над MCC при определении категории.
- MCC остаётся как fallback, если ни один title-паттерн не совпал.
- Схема конфига (`categoryMapping`) не меняется.

**Non-Goals:**
- Изменение самих title-паттернов или MCC-маппинга в конфиге.
- Поддержка "условного MCC" (MCC + дополнительное title-условие).
- Logging конфликтов title/MCC (не нужно — title явно приоритетнее по дизайну).

## Decisions

### 1. Порядок: title → MCC (а не удаление MCC)

MCC-маппинг сохраняем как fallback. Альтернатива — удалить MCC-маппинг совсем и перевести всё на title — требует полного покрытия title-паттернами всех известных MCC, что сейчас не выполнено. Потеря категорий для транзакций без title-паттерна неприемлема.

### 2. Изменение только `mapTochkaCategory`

Логика изолирована в одной функции. Менять call site или структуру `CategoryMapping` не нужно. Это минимальное хирургическое изменение.

### 3. Без logging'а конфликтов

Когда title побеждает MCC — это штатное поведение по новому дизайну, не edge case. Логировать нечего.

## Risks / Trade-offs

**[Риск] Title-паттерн написан слишком широко и захватывает нежелательные транзакции** → Mitigation: это риск конфига, не кода. Тесты с конкретными примерами (AVTOSERVIS) фиксируют ожидаемое поведение и защищают от регрессий при редактировании конфига.

**[Trade-off] Title-паттерны в конфиге теперь имеют неявно высокий приоритет** → Разработчик, добавляющий широкий паттерн (например, `/.*/`), перекроет весь MCC-маппинг для совпадающих транзакций. Это задокументировано поведение — порядок проверки определяет приоритет.

## Engineering Constraints

- TypeScript strict mode: сигнатура `mapTochkaCategory` не меняется, типы не затронуты.
- Biome lint: перестановка двух блоков кода не вводит новых паттернов, которые могут нарушить правила.
- Модульная граница: изменение строго внутри `tochka.ts`, экспортируемый интерфейс не меняется.
- `npm run check` должен проходить без изменений в других файлах.
