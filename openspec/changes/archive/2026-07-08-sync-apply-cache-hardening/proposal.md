## Why

При повторном `apply` на устаревшем HM-кэше создаются дублирующиеся транзакции: если оператор забыл обновить кэш после предыдущего `apply`, только что созданные записи не распознаются как «внесённые» и отправляются повторно. Дополнительно `sync` оставляет старый файл предыдущей синхронизации, из-за чего `apply` падает на инварианте «ровно один файл», а печать проблемных записей содержит лишнее ветвление через `normalized`.

## What Changes

- **Форсированное обновление HM-кэша в `apply`.** `apply` обновляет локальный HM-кэш перед skip-pass на любом запуске (включая `--preview` и `--preview-planned`). Граница обрезки кэша (`from`) берётся из имени sync-файла (`sync/<source>/<from>_<to>.json`).
- **Новый опт-аут `--skip-hmbee-cache-update` на `apply`** для офлайн/тестовых прогонов на существующем кэше.
- **BREAKING: удаление флага `--update-hmbee-cache` из команды `sync`.** Владельцем обновления кэша становится `apply`; `sync` больше не обращается к Honey Money.
- **Автоочистка в `sync`.** Перед записью нового sync-файла команда удаляет прочие `*.json` в `sync/<source>/` (только в файловом режиме; при `--stdout` директория не затрагивается; каталог `sync/hmbee/` не задевается).
- **Loader возвращает данные вместе с границами интервала.** `loadSyncFiles` отдаёт записи вместе с распарсенными `from`/`to`, чтобы `apply` мог вычислить границу обрезки кэша без отдельного разбора имени файла.
- **Упрощение печати проблемных записей** (implementation-only, без изменения требований): id и описание всегда берутся через `describeSourceRecord(sourceRecord)`, ветка через `normalized` убирается.

### Modified Capabilities
- `source-apply`: `apply` обязан обновлять HM-кэш перед skip-pass на любом запуске, с опт-аутом `--skip-hmbee-cache-update`; отказ обновления прерывает `apply`.
- `source-sync`: команда удаляет предыдущий sync-файл в `sync/<source>/` перед записью нового (файловый режим); флаг `--update-hmbee-cache` удаляется.
- `hmbee-transaction-cache`: обновление кэша инициируется командой `apply` (а не флагом `sync`), граница обрезки берётся из имени sync-файла.

## Impact

- **Код**: `src/index.ts` (команды `sync` и `apply`), `src/apply/preview/loader.ts` (возврат `from`/`to`), `src/hmbee/cache.ts` (переиспользование trimming в apply).
- **CLI-контракт (BREAKING)**: `sync --update-hmbee-cache` удаляется; на `apply` появляется `--skip-hmbee-cache-update`.
- **Побочный эффект**: `apply --preview` теперь по умолчанию требует HM-креды и сеть (кроме как под `--skip-hmbee-cache-update`).
- **Документация**: упоминания `--update-hmbee-cache` в README/скриптах/TECH-DEBT требуют обновления.
- **Quality gate**: изменения покрываются существующими тестами + новыми юнит-тестами; `npm run check` (Biome + tsc strict) должен проходить.
