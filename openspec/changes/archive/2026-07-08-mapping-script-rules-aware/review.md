## Findings

### 🔴 CRITICAL

Нет.

### 🟡 WARNING

- **W1. `saveJsonFile` конфликтует с Biome-форматированием конфига** (pre-existing, проявилось на quality gate). `JSON.stringify(data, null, 2)` раскладывает короткие массивы (например, `ignored.title`) по строкам, а Biome требует однострочную форму → после обычной сессии скрипта `npm run check` падает на `config/sources.json` до ручного `npx biome format --write config/sources.json`. Рекомендация: после записи конфига прогонять Biome-форматирование (или исключить `config/*.json` из Biome-скоупа осознанным решением).
- **W2. Потеря строк stdin при не-TTY вводе** (pre-existing). При пайпе ответов одним чанком `readline` теряет строки, пришедшие до регистрации следующего `question` («readline was closed»). Интерактивную работу не затрагивает; мешает только скриптованным прогонам. Рекомендация: иметь в виду при автоматизированном тестировании; лечится очередью строк через событие `line`.

### 🟢 SUGGESTION

- **S1. Boolean-флаг `useMatches` в `buildRule`**. Флаговый параметр читается хуже, чем передача готового условия (или выбор условия внутри `buildRule`). Некритично — функция локальная для скрипта.
- **S2. Порядок операндов `==`**. Скрипт пишет `{"==": [{var}, value]}` (по спеке), а исправленные вручную правила в конфиге — `{"==": [value, {var}]}`. Оба варианта эквивалентны в json-logic; чисто косметическая неоднородность конфига.
- **S3. `getDescription(entry) ?? ""` для «грязных» записей**. Запись без description резолвится с пустой строкой (промпт), тогда как рантайм такую запись фейлит («Missing source title field»). Поведение осознанное по design («не падать на грязных записях»), фиксируется здесь для прозрачности.
