## Why

Runtime уже поддерживает расширенные правила категории `hmbee.categoryMapping.rules` (change `additional-attributes-for-category-mapping`), но создавать их можно только вручную, редактируя `config/sources.json`. Интерактивный скрипт `scripts/tochka-mapping.js` (`npm run map:tochka`) умеет заполнять только `mcc`/`title`. Нужно дать оператору возможность создавать правила прямо из скрипта, проходя по записям sync. Это follow-up задача 7.1 родительского change.

## What Changes

- Добавить в `scripts/tochka-mapping.js` новую команду `r, <field>, <Категория>[, <Описание>]`, создающую расширенное правило и дописывающую его в конец `hmbee.categoryMapping.rules`.
- Правило строится по устойчивой идиоме `AND(type_code == <тип текущей записи>, matches(<полное содержимое record.data.<field>>, record.data.<field>))`. Guard по `type_code` добавляется всегда (вариант без guard не поддерживается).
- Валидация: если `record.data.<field>` отсутствует или пустое — правило не создаётся, печатается предупреждение, возврат к промпту той же записи (защита от опечатки в имени поля и от поля, отсутствующего у типа записи).
- Расширить инфо-строку по каждой записи полями `type_code` и `event_date`, чтобы оператор мог принять решение и найти транзакцию в исходном файле.
- Скрипт правила **только создаёт** (строит JS-объект и пишет в конфиг), не вычисляет их — без `json-logic-js` в скрипте, без дублирования оператора `matches`.

Не в объёме (out-of-scope):
- Авто-пропуск (дедуп) остаётся только по `title`/`mcc`; правила `rules[]` в авто-пропуске не участвуют. Осознанное ограничение: запись, покрытая только правилом, будет переспрошена.
- Сужение подстроки в `matches` и экранирование regex — ручная правка конфига оператором (корректность паттерна на операторе, как и для title-паттернов).
- Запись по-прежнему только в `config/sources.json`.

### Modified Capabilities
- `tochka-category-mapping`: добавляется требование к скрипту `tochka-mapping.js` — интерактивное создание расширенных правил командой `r` (с guard по type_code, валидацией наличия поля) и расширенный вывод записи (`type_code`, `event_date`).

## Impact

- `scripts/tochka-mapping.js`: парсинг команды `r`, построение объекта правила, запись в `hmbee.categoryMapping.rules`, расширенный вывод записи, валидация поля.
- `config/sources.json`: заполняется ключ `hmbee.categoryMapping.rules` (структура уже поддержана runtime).
- Зависимости: без изменений (скрипт правила не вычисляет).
- Quality gate: `npm run check` (typecheck + Biome lint + vitest) должен проходить.
