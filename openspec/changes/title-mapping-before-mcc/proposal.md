## Why

При определении категории транзакции MCC-код слишком широк: один код (например, 7538 — автосервисы) покрывает семантически разные операции (шиномонтаж, авторемонт). Title транзакции точнее описывает конкретный merchant — поэтому при наличии совпадающего title-паттерна он должен иметь приоритет над MCC.

Конкретный триггер: транзакция AVTOSERVIS с mcc=7538 получила категорию "Автомобиль / Ремонт" (от MCC), хотя title-паттерн должен был дать "Автомобиль / Шиномонтаж" — категорию, которая стоит на плановой транзакции. Из-за этого matching планов не сработал.

## What Changes

- В функции `mapTochkaCategory` (tochka.ts) порядок проверки меняется: title-паттерны → MCC (было: MCC → title-паттерны).
- MCC по-прежнему используется как fallback, если ни один title-паттерн не совпал.
- Поведение транзакций без title-паттерна не изменится.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `tochka-category-mapping`: меняется приоритет резолюции категории — title-паттерны теперь имеют приоритет над MCC.

## Impact

- **Код**: только функция `mapTochkaCategory` в `src/apply/preview/tochka.ts` (единственный call site — строка 633).
- **Конфиг**: изменений в схеме конфига не требуется.
- **Тесты**: нужно добавить тест на сценарий "title совпадает, MCC тоже есть — побеждает title" и "MCC как fallback если title не совпал".
- **Риск регрессий**: минимальный — title-паттерны в конфиге явные regex'ы. Транзакции без title-совпадения поведения не меняют.
- **Quality gates**: `npm run check` (TypeScript strict + Biome), существующие тесты preview.
