# Правила работы с OpenSpec

- При выполнении apply (`/opsx:apply` и аналоги) — перед началом работы спросить человека, в каком режиме выполнять задачи:
  1. **Все задачи подряд** — выполнить все задачи от начала до конца без остановок, пока не будут выполнены все задачи или не возникнет неразрешимый блокер.
  2. **По группам** — выполнять пошагово по группам задач (секции `## N. ...` в `tasks.md`), с остановкой после каждой группы. После завершения всех задач одной группы — остановиться, кратко резюмировать изменения и дождаться подтверждения человека, прежде чем переходить к следующей группе.

- **Автокоммит по подзадачам.** При выборе любого из двух режимов дополнительно спросить пользователя, нужно ли коммитить изменения после каждой выполненной подзадачи (без push в origin). Если да — запросить у пользователя FEATURE-ID (например, `HMB-XX`) и после каждой подзадачи коммитить с сообщением вида:

  ```
  [FEATURE-ID] Apply. Task X.X <description>
  ```

  где `X.X` — номер подзадачи, `<description>` — краткое описание на русском.

  Это единственное исключение из правила «агент коммитит только по явной просьбе человека» (см. AGENTS.md) — действует только при явном выборе автокоммита в диалоге и никогда не включает push.

- **Отметка в tasks.md коммитится вместе с подзадачей, не отдельно в конце.** Как только подзадача `X.X` выполнена, `- [ ]` → `- [x]` для неё правится и попадает в тот же коммит `[FEATURE-ID] Apply. Task X.X ...`, что и код этой подзадачи — не откладывается на отдельный завершающий коммит после прохода по всем задачам.

  Автокоммит действует только в момент, когда подзадача выполняется впервые как часть прохода по `tasks.md`. Любой follow-up после этого в рамках диалога (правка, багфикс, ответ на «поправь X», ad hoc доработка, не являющаяся отдельной подзадачей из `tasks.md`) — **не коммитится автоматически**, даже если он относится к уже закоммиченной подзадаче. Сделать правку, показать диф и ждать явного «закоммить» или запроса, однозначно продолжающего согласованную подзадачу.
