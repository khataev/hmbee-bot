# HMBee Bot

CLI-утилита на TypeScript для синхронизации финансовых операций из различных источников в сервис [Honey Money](https://honeymoney.me/).

## 🎯 Цель проекта
Автоматизировать (или упростить ручной) импорт данных из банков, которые не имеют прямой интеграции с Honey Money, при соблюдении принципов безопасности и прозрачности для пользователя.

## 🚀 Текущий статус: MVP (Этап 1)
На данном этапе реализован базовый CLI-скелет и поддержка синхронизации из дебет-карты **Точка Банка** через использование данных текущей браузерной сессии.

### Основные возможности:
- **`list`**: Просмотр доступных источников данных.
- **`sync <source>`**: Загрузка транзакций за указанный период с сохранением результата в `sync/<source>/<from>_<to>.json`. Перед записью удаляет прочие `*.json` в `sync/<source>/`, чтобы оставался ровно один файл (`--stdout` директорию не трогает).
- **`apply <source>`**: Перед сопоставлением обновляет локальный кеш транзакций Honey Money (`sync/hmbee/all_json_cache.json`, обрезка по `<from> − 10 дней` из имени sync-файла), затем помечает уже внесённые транзакции как `save=false` с причиной `"Внесена вручную"`, сопоставляет остальные с неподтверждёнными плановыми транзакциями и отправляет идентифицированные в Honey Money. Сматченные с планом записи подтверждаются через `POST /transaction` с `id` плана (confirm-путь); не сматченные — создаются (create-путь).
- **`apply <source> --skip-hmbee-cache-update`**: Пропускает обновление кеша Honey Money и работает на уже существующем файле кеша (офлайн/тестовые прогоны).
- **`apply <source> --preview`**: Предпросмотр полного draft-представления транзакции для Honey Money (включая пропущенные и сматченные с планом).
- **`apply <source> --preview-planned`**: Предпросмотр только plan-relevant записей (сматченные `matched-*` и кандидаты `out-of-tolerance`/`ambiguous`) вместе с несматченными плановыми транзакциями источника за рассматриваемый период. Записи `no-candidate` исключаются.
- **`apply <source> --only-id ...`**: Отправка только выбранных идентифицированных транзакций по списку source id.
- **`apply <source> --one-by-one`**: Перед каждой отправкой (create или confirm) печатает однострочную сводку и запрашивает ввод: `y` — отправить, `n` — пропустить, `a` — отправить все оставшиеся без запросов, `q` — выйти. Инертен в `--preview`/`--preview-planned`.
- Поддержка экспорта в `raw` (исходный JSON от банка) или `adapted` (нормализованный вид) форматы.
- Вывод результата в консоль или сохранение в файл.

## 🛠 Установка и настройка

1. **Клонирование и зависимости**:
   ```bash
   npm install
   ```

2. **Настройка окружения**:
   Создайте файл `.env` на основе примера. Для работы с Точкой нужен `TOCHKA_CUSTOMER_ID`. Session-cookie для Точки забирается автоматически из sessionstore работающего Firefox с активной сессией на `i.tochka.com` — вручную задавать `TOCHKA_COOKIE` не нужно. Если Firefox недоступен (не установлен, не запущен, либо cookie в нём не нашлась), используется fallback-значение из `TOCHKA_COOKIE` в `.env`, если оно задано. Для записи в Honey Money заполните `HM_USER_EMAIL` и `HM_USER_TOKEN`; остальные HM-параметры берутся из `.env.example` и при необходимости могут быть переопределены.

3. **Конфигурация**
   Скопируйте файл конфигурации и замените идентификаторы счетов Honey Money на реальные:
   ```bash
   cp config/sources.example.json config/sources.json
   ```


## 📖 Использование

### Список источников
```bash
npx tsx src/index.ts list
```

### Синхронизация данных
Пример получения данных из Точки за январь 2024:
```bash
npx tsx src/index.ts sync tochka --from 2024-01-01 --to 2024-01-31
```

По умолчанию результат будет сохранен в `sync/tochka/2024-01-01_2024-01-31.json`, при этом прочие `*.json` в `sync/tochka/` удаляются, чтобы оставался только один файл. Если нужен вывод в stdout, используйте `--stdout` (директория `sync/tochka/` в этом режиме не затрагивается).

### Обновление кеша Honey Money

Любой вызов `apply` (включая `--preview` и `--preview-planned`) перед сопоставлением обновляет локальный кеш транзакций Honey Money — это гарантирует, что повторный `apply` не создаст дубли уже отправленных записей. Обновление требует HM-креды и сеть; для офлайн/тестовых прогонов на существующем кеше используйте `--skip-hmbee-cache-update`:
```bash
npx tsx src/index.ts apply tochka --preview --skip-hmbee-cache-update
```

### Предпросмотр нормализованных данных
Команда `apply --preview` позволяет проверить, как транзакции будут выглядеть после нормализации и маппинга категорий:
```bash
npx tsx src/index.ts apply tochka --preview
```

### Предпросмотр сопоставления с плановыми транзакциями
Команда `apply --preview-planned` показывает только записи, связанные с плановыми транзакциями (сматченные и кандидаты), и несматченные планы источника — чтобы выделить их «из толпы» без `jq`:
```bash
npx tsx src/index.ts apply tochka --preview-planned
```

### Отправка в Honey Money
Команда `apply` отправляет идентифицированные записи в Honey Money и печатает пары source/Honey Money id в JSON:
```bash
npx tsx src/index.ts apply tochka
```

Записи, сматченные с неподтверждённым планом, подтверждают план (`POST /transaction` с `id`). Остальные создаются как новые транзакции. Verbose-режим печатает счётчики created/confirmed.

### Отправка только выбранных транзакций

```bash
npx tsx src/index.ts apply tochka --only-id 4223584703,4223565341
```

Если указан `--only-id`, команда все равно работает только с уже идентифицированными записями, а затем дополнительно ограничивает отправку переданным списком source transaction id.

### Ручное подтверждение каждой отправки (--one-by-one)

```bash
npx tsx src/index.ts apply tochka --one-by-one
```

Перед каждой отправкой печатает однострочную сводку (`дата · тип · категория · описание [create|confirm #id]`) и ждёт ввода: `y` — отправить, `n` — пропустить, `a` — отправить все оставшиеся без запросов, `q` — выйти.

## ✅ Качество кода

В проекте используется единый инструмент качества: **Biome** (lint + format).
